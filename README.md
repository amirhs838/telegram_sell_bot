# پلتفرم فروشگاهی تلگرام — Telegram Commerce Platform

یک MVP آماده‌ی تولید (production-ready) از یک پلتفرم فروشگاهی مبتنی بر تلگرام. فروشنده فروشگاه را از پنل مدیریت فارسی/راست‌چین مدیریت می‌کند؛ مشتریان از طریق ربات تلگرام مرور و سفارش ثبت می‌کنند؛ **پایگاه داده تنها مرجع حقیقت (single source of truth)** است و پست‌های کانال تلگرام همیشه با آن **همگام** می‌مانند.

> ⚠️ این یک MVP است. امنیت، مقیاس‌پذیری و یکپارچه‌سازی‌ها در حدِ منطقیِ یک MVP هستند (بخش [محدودیت‌های شناخته‌شده](#-محدودیت‌های-شناختهشده) را ببینید).

## ✨ امکانات

| ماژول | شرح |
|---|---|
| **احراز هویت مدیر** | ورود مبتنی بر سشن (bcrypt + سشن در دیتابیس + کوکی httpOnly)، محدودسازی نرخ درخواست (rate-limit)، تغییر رمز عبور |
| **داشبورد** | ۷ شاخص کلیدی (تعداد محصولات، فعال، کم‌موجودی، ناموجود، سفارش‌های در انتظار، سفارش‌های امروز، مجموع فروش)، نمودار فروش/سفارش ۷ روز اخیر، سفارش‌های اخیر |
| **محصولات** | CRUD کامل، جستجو/فیلتر/مرتب‌سازی/صفحه‌بندی، آپلود تصویر با پیش‌نمایش، انتشار/لغو انتشار در کانال، همگام‌سازی خودکار وضعیت↔موجودی |
| **دسته‌بندی‌ها** | CRUD همراه با تعداد محصولات، تولید اسلاگ فارسی |
| **انبار و موجودی** | کسر موجودی در قالب تراکنش، تغییر وضعیت خودکار به «ناموجود»، بازگشت موجودی هنگام لغو سفارش، مقاوم در برابر رقابت همزمان (گارد SQL ‏`stock >= qty`) |
| **تولید محتوای هوش مصنوعی** | ورودِ خام فارسی → عنوان/توضیحات/پیشنهاد دسته‌بندی/برچسب‌ها/کپشن تلگرام ساختاریافته — همیشه پیش‌نمایش + اعمال صریح، هرگز قیمت/موجودی از خودش نمی‌سازد |
| **کانال تلگرام** | انتشار پست محصول (با دکمه لینک مستقیم سفارش 🛒)، همگام‌سازی خودکار هنگام تغییر قیمت/نام/توضیح/موجودی/وضعیت (همان پست ویرایش می‌شود، بدون پست تکراری)، حالت‌های 🔴 ناموجود / ⚠️ کم‌موجودی |
| **اتصال از پنل** | فروشنده بدون ویرایش env، ربات/کانال خودش را از پنل وصل می‌کند: راهنمای گام‌به‌گام فارسی، تأیید زنده توکن/کانال/چت، فعال‌سازی خودکار بدون ری‌استارت، قطع اتصال با یک کلیک |
| **ربات تلگرام** | `/start` `/products` `/orders` `/help`، مرور دسته‌بندی، جستجو، لینک مستقیم ‏`?start=product_<id>`، جریان سفارش مکالمه‌ای (تعداد → نام → موبایل → آدرس → خلاصه → تأیید) |
| **سفارش‌ها** | ایجاد تراکنشی همراه با اسنپ‌شات قیمت/نام، چرخه حیات ۶ حالته، دکمه‌های ✅ تأیید / ❌ لغو در تلگرام برای فروشنده، بازگشت موجودی هنگام لغو، اعلان به مشتری |
| **مشتریان** | ایجاد خودکار از تلگرام، آمار هر مشتری (تعداد سفارش، مجموع خرید، آخرین سفارش) |
| **اعلان فروشنده** | هر سفارش جدید → هشدار تلگرام با دکمه‌های شیشه‌ای ✅ تأیید / ❌ لغو |
| **دستیار هوش مصنوعی (ابزارمحور)** | پاسخ به سؤالات آزاد مشتری از طریق فراخوانی ابزار (`search_products`، `get_product`، `check_stock`، `get_categories`، `get_customer_orders`) — فقط داده‌های واقعی |
| **آماده‌ی RAG** | بردارِ تعبیه (embedding) محصولات (سرویس‌پذیر، بردارساز محلی ۲۵۶بعدی با نرمال‌سازی فارسی)، جستجوی معنایی ترکیبی با فیلترهای ساختاریافته |
| **آزمایشگاه ربات (Bot Lab)** | شبیه‌ساز گفتگوی داخل پنل مدیریت برای اجرای کامل جریان ربات بدون توکن واقعی تلگرام |
| **لاگ‌ها** | خروجی JSON ساختاریافته + جدول `ActivityLog` (سفارش‌ها، انتشار/همگام‌سازی، هوش مصنوعی، خطاهای احراز هویت)؛ اسرار (secrets) حذف می‌شوند |
| **تنظیمات** | نام/توضیحات فروشگاه، آیدی پشتیبانی؛ وضعیت پیکربندی تلگرام (اسرار فقط از طریق env/دیتابیس) |

## 🏗 معماری

```
فروشنده ──> پنل مدیریت (SPA در "/" — مسیریابی hash، راست‌چین، shadcn/ui)
             │
             ▼
        مسیرهای API در Next.js (/api/**)  ← احراز هویت با کوکی سشن
             │
             ▼
   Prisma + SQLite (WAL)  ← تنها مرجع حقیقت (تنظیمات تلگرام هم اینجاست)
             ▲                        │
             │ دسترسی مستقیم Prisma   │ انتشار / همگام‌سازی / اعلان
   mini-services/bot-service          ▼
   (پورت 3002، bun --hot)      Telegram Bot API (long-polling پویا)
             ▲
   /simulate  ◀── آزمایشگاه ربات مدیر (پروکسی از طریق /api/bot/simulate)
   دستیار AI ◀── HTTP داخلی با x-internal-key (/api/internal/ai-assistant)
```

- **SPA تک‌مسیره** — پیش‌نمایش سندباکس فقط مسیر `/` را نمایش می‌دهد، پس همه‌ی ناوبری بر اساس hash است (`#/products`، `#/orders` و…).
- **ربات = سرویس مستقل bun** — ماشین حالت مکالمه (`BotSession`) را مدیریت می‌کند، سفارش‌ها را تراکنشی از طریق Prisma ثبت می‌کند و نقطه‌پایان داخلی AI در Next.js را صدا می‌زند. SQLite WAL + محدودیت اتصال، اجرای دوپروسه‌ای را امن می‌کند؛ گارد شرطی ‏`UPDATE … WHERE stock >= qty` کسر موجودی را در برابر رقابت ایمن می‌سازد.
- **پیکربندی پویا** — تنظیمات تلگرام (توکن/کانال/چت مدیر/یوزرنیم) با اولویت «پنل (دیتابیس) > env» در هر فراخوانی حل می‌شود؛ سرویس ربات هر ~۱۵ ثانیه دیتابیس را بازخوانی می‌کند و حلقه polling در حالت mock می‌خوابد و با اتصال واقعی خودکار بیدار می‌شود.
- **حالت شبیه‌سازی تلگرام** — بدون توکن (یا با `TELEGRAM_MOCK=true` وقتی پنل متصل نیست) همه‌ی فراخوانی‌های تلگرام شبیه‌سازی و در `ActivityLog` ثبت می‌شوند (`telegram_out`)؛ بنابراین کل چرخه‌ی انتشار→همگام‌سازی→سفارش→اعلان بدون اطلاعات واقعی قابل دمو است.
- **پول** = تومان (عدد اعشاری)، قالب‌بندی `fa-IR`. **اسنپ‌شات** — اقلام سفارش، نام/قیمت محصول را در لحظه‌ی خرید ذخیره می‌کنند.

## 🚀 راه‌اندازی

```bash
bun install
cp .env.example .env          # مقادیر را ویرایش کنید (پایین را ببینید)
bun run db:push               # ساخت/همگام‌سازی اسکیمای SQLite
bun scripts/seed.ts           # داده‌های نمونه (با --reset پاک‌سازی و بذر مجدد)
bun run dev                   # Next.js روی http://localhost:3000
cd mini-services/bot-service && bun run dev   # سرویس ربات روی :3002
```

ورود: **admin@shop.local / admin1234**

### متغیرهای محیطی (`.env`)

| متغیر | شرح |
|---|---|
| `DATABASE_URL` | ‏`file:/abs/path/db/custom.db?connection_limit=2` |
| `INTERNAL_API_KEY` | رمز مشترک بین Next API و سرویس ربات (`openssl rand -hex 24`) |
| `TELEGRAM_BOT_TOKEN` | از [@BotFather](https://t.me/BotFather) — خالی ⇒ حالت شبیه‌سازی (یا اتصال از پنل) |
| `TELEGRAM_CHANNEL_ID` | شناسه عددی `-100…` (ربات باید مدیر کانال باشد) |
| `TELEGRAM_ADMIN_CHAT_ID` | چت فروشنده که هشدارهای سفارش را دریافت می‌کند |
| `TELEGRAM_BOT_USERNAME` | یوزرنیم ربات (بدون @) برای لینک‌های مستقیم ‏`t.me/<bot>?start=product_<id>` |
| `TELEGRAM_MOCK` | ‏`true` = شبیه‌سازی محلی تلگرام (فقط وقتی پنل متصل نیست) |

هرگز اطلاعات واقعی را کامیت نکنید. اسرار هرگز توسط API برگردانده نمی‌شوند (فقط فلگ بولی «تنظیم‌شده/نشده» و توکن ماسک‌شده).

### پایگاه داده

- اسکیمای Prisma: ‏`prisma/schema.prisma` (کاربران، سشن‌ها، دسته‌بندی‌ها، محصولات، مشتریان، سفارش‌ها، اقلام سفارش با اسنپ‌شات، نگاشت `telegram_products`، بردارهای محصولات (`product_embeddings`)، سشن‌های ربات، تنظیمات، لاگ فعالیت، شمارنده‌ها).
- Push: ‏`bun run db:push` · Migrate: ‏`bun run db:migrate` · Seed: ‏`bun scripts/seed.ts [--reset]`
- شماره سفارش‌ها از جدول `Counter` داخل تراکنش سفارش می‌آید (بذر از ۱۰۰۶ شروع می‌کند ⇒ اولین سفارش جدید = ‏#1007).

### داده‌های نمونه (Seed)

۵ دسته‌بندی · ۱۰ عکس محصول تولیدشده با هوش مصنوعی (`upload/seed-*.png`) · ۱۰ محصول (نمونه‌های کم‌موجودی، ناموجود، غیرفعال، پیش‌نویس) · ۴ مشتری · ۶ سفارش در همه‌ی وضعیت‌ها (#1001–1006) · بردارهای تعبیه برای همه‌ی محصولات.

## 📡 راه‌اندازی تلگرام

### اتصال از پنل مدیریت (روش پیشنهادی) 🔌

بخش **«تلگرام و ربات»** پنل، کارت «اتصال ربات و کانال تلگرام» را دارد؛ فروشنده بدون ویرایش هیچ فایلی، ربات و کانال خودش را همان‌جا وصل می‌کند:

1. دکمه **«راهنمای گام‌به‌گام»** را باز کنید — پنج مرحله فارسی: ساخت ربات با @BotFather، مدیرکردن ربات در کانال، گرفتن شناسه کانال از @userinfobot، گرفتن شناسه چت خودتان، و یوزرنیم ربات.
2. چهار فیلد را پر کنید: **توکن ربات** (با دکمه نمایش/پنهان)، **شناسه کانال** (`-100…` یا `@username`)، **شناسه چت مدیر** (اعلان سفارش‌ها)، **یوزرنیم ربات** (بدون @).
3. **«ذخیره و اتصال»** را بزنید — توکن/کانال/چت به‌صورت زنده از طریق Bot API تأیید می‌شوند و نتیجه هر مورد (✅/❌ با پیام فارسی) همان‌جا نمایش داده می‌شود.
4. اتصال جدید **بدون ری‌استارت** ظرف حداکثر ~۳۰ ثانیه در سرویس ربات فعال می‌شود (کش تنظیمات هر ۱۵ ثانیه بازخوانی می‌شود و حلقه polling خودکار شروع/جابه‌جا می‌شود).
5. **«تست اتصال»** در بالای صفحه تشخیص کامل می‌دهد: getMe ربات، دسترسی کانال، در دسترس بودن چت مدیر و ارسال پیام آزمایشی.
6. **«قطع اتصال»** تنظیمات پنل را حذف می‌کند و سیستم به env/حالت شبیه‌سازی برمی‌گردد.

نکات امنیتی: توکن فقط در جدول `Setting` سرور ذخیره می‌شود، هرگز کامل به کلاینت برگردانده نمی‌شود (فقط ماسک `••••1234`) و همه مسیرهای config نیاز به ورود مدیر دارند. اولویت پیکربندی: **پنل (دیتابیس) > متغیرهای محیطی**؛ اتصال از پنل حالت `TELEGRAM_MOCK=true` را هم بی‌اثر می‌کند.

**سفارش از کانال → ربات**: پست‌های کانال دکمه‌ی `🛒 سفارش در ربات` دارند که به ‏`https://t.me/<bot>?start=product_<id>` لینک می‌شود؛ ربات مستقیماً جریان سفارش همان محصول را باز می‌کند.

## 🤖 راه‌اندازی هوش مصنوعی

هوش مصنوعی روی `z-ai-web-dev-sdk` اجرا می‌شود (فقط سمت بک‌اند) — در این محیط به کلید اضافه نیازی نیست:

- ‏`POST /api/ai/generate-content` — محتوای ساختاریافته‌ی محصول (اعتبارسنجی با zod؛ خروجی پیش‌نمایش می‌شود و فقط با اقدام صریح فروشنده اعمال می‌گردد).
- بردارهای تعبیه — جدول `ProductEmbedding` + سرویس‌دهنده‌ی `local-hash-v1` ‏(`src/lib/ai/embedding.ts`): bag-of-words هش‌شده + کاراکتر ۳گانه‌ها با نرمال‌سازی فارسی، ۲۵۶بعدی، شباهت کسینوسی. هنگام ذخیره‌ی محصول خودکار ساخته می‌شود؛ دکمه‌ی **بازسازی بردارها** در «ابزارهای هوش مصنوعی» همه را از نو می‌سازد. برای RAG کامل، سرویس‌دهنده را با یک API واقعی تعبیه جایگزین کنید.
- دستیار — ‏`src/lib/ai/assistant.ts` حلقه‌ی ابزار JSON (حداکثر ۴ تکرار). قواعد الزامی در پرامپت سیستم نوشته شده: هرگز محصول/قیمت/موجودی/سفارش از خودش نسازد؛ داده‌ی نهایی همیشه از نتیجه‌ی ابزارها (دیتابیس) بیاید. اگر AI در دسترس نباشد، ربات به جستجوی قطعی (deterministic) برمی‌گردد.

## 🧪 تست‌های انجام‌شده (به‌صورت سرتاسری تأیید شده)

- ورود/خروج/محدودسازی نرخ/تغییر رمز؛ مسیرهای محافظت‌شده کد 401 برمی‌گردانند؛ ورود با اطلاعات اشتباه پیام درست «ایمیل یا رمز عبور اشتباه است» را نشان می‌دهد.
- CRUD دسته‌بندی و محصول از طریق UI؛ اسلاگ فارسی؛ آپلود تصویر → پیش‌نمایش → ذخیره‌ی ماندگار؛ اعتبارسنجی آپلود (نوع/حجم).
- تولید محتوای AI از ورودی خام فارسی → پیش‌نمایش → اعمال کامل؛ بدون ساختن قیمت/موجودیِ ساختگی؛ پیشنهاد دسته‌بندی اعمال شد.
- انتشار → ساخت پست + نگاشت `telegram_products` (پیام شبیه‌سازی‌شده‌ی `sendMessage` در لاگ)؛ ویرایش قیمت → `editMessageText` روی **همان** پست، مبتنی بر مقایسه هش، بدون پست تکراری؛ موجودی صفر → پست 🔴 ناموجود + وضعیت محصول `out_of_stock`؛ شارژ مجدد → دکمه برگشت.
- اتصال از پنل (تأیید شده در مرورگر): اعتبارسنجی فارسی همه فیلدها؛ ذخیره → ماسک توکن + منبع «پنل»؛ تأیید زنده با توکن جعلی → خطای Unauthorized با راهنمای فارسی؛ فعال‌سازی خودکار سرویس ربات (`/health` → `mode:"real"`) بدون ری‌استارت؛ قطع اتصال → بازگشت خودکار به شبیه‌سازی.
- جریان کامل سفارش در آزمایشگاه ربات: مرور → سفارش → تعداد (درخواست بیش از موجودی با اعلام موجودی زنده رد می‌شود) → اعتبارسنجی نام/موبایل/آدرس → خلاصه → تأیید → **تراکنش دیتابیس** (کسر موجودی، شماره سفارش، اسنپ‌شات‌ها، upsert مشتری) → ثبت اعلان فروشنده.
- تغییر وضعیت توسط فروشنده → اعلان به مشتری (شبیه‌سازی) در لاگ؛ لغو → بازگشت موجودی تأیید شده.
- دستیار AI: «یه کفش سفید برای پیاده‌روی تا دو میلیون میخوام» → `search_products` → محصولات واقعی زیر ۲ میلیون با قیمت/موجودی واقعی.
- محصول ناموجود: از مرور پنهان، لینک مستقیم رد می‌شود، دکمه سفارش ندارد.
- چیدمان موبایل/دسکتاپ، فوتر چسبان، بدون خطای کنسول، lint پاک.

## 📦 استقرار (Deployment)

1. برای تولید، Postgres تهیه کنید — ‏`datasource db.provider` را به `"postgresql"` تغییر دهید، `DATABASE_URL` را به‌روز کنید و `prisma migrate deploy` را اجرا کنید. (ستون تعبیه فعلاً JSON است؛ با رشد حجم، به `pgvector` مهاجرت کنید.)
2. ‏`bun run build && bun run start` (یا Docker). سرویس ربات را به‌عنوان پروسه‌ی دوم اجرا کنید؛ هر دو دیتابیس مشترک دارند.
3. یک دامنه‌ی عمومی HTTPS جلوی سرویس‌ها بگذارید؛ تلگرام را با long-polling (پیش‌فرض) به ربات وصل کنید یا `bot-service` را پشت گیت‌وی برای وب‌هوک نمایش دهید.
4. همه‌ی اسرار را به‌صورت متغیر محیطی در هاست/CI تنظیم کنید (یا از اتصال از پنل استفاده کنید).

| اتصال ذخیره شد ولی «تأیید توکن ناموفق بود» | توکن را با @BotFather چک کنید؛ «تست اتصال» را دوباره بزنید |
| ربات جواب می‌دهد ولی یادداشت «AI در دسترس نیست» می‌آید | مشکل SDK/شبکه‌ی هوش مصنوعی — ربات به جستجو برمی‌گردد؛ لاگ‌های `ai.*` را در ActivityLog ببینید |
| `SQLITE_BUSY` / قفل‌شدگی | `connection_limit=2` را در هر دو سرویس نگه دارید؛ WAL روی فایل دیتابیس فعال است |
| بازنشانی داده‌های نمونه | ‏`bun scripts/seed.ts --reset` |

## ⚠️ محدودیت‌های شناخته‌شده

- امنیت MVP: ‏bcrypt + کوکی httpOnly + محدودسازی نرخ + اعتبارسنجی zod + حذف اسرار از لاگ؛ هنوز 2FA/توکن CSRF/CSP ندارد. در حالت polling، به‌روزرسانی‌های تلگرام امضاسنجی نمی‌شوند. توکن رباتِ ذخیره‌شده در دیتابیس رمزنگاری‌شده نیست (فقط ماسک در API) — برای محیط‌های حساس، رمزنگاری در سطح فیلد اضافه کنید.
- ذخیره‌سازی تصویر روی دیسک محلی (`upload/`) پشت یک مسیر عمومی است — پیش از ترافیک واقعی، ماژول ذخیره‌سازی را با S3/CDN جایگزین کنید؛ تلگرام در پست‌ها فقط URL مطلق تصویر را رندر می‌کند.
- محدودساز نرخ در حافظه و کش‌های هرپروسه‌ای — فقط برای تک‌نمونه مناسب است.
- بردارهای تعبیه، بردارهای هش محلی (شباهت واژگانی) هستند نه تعبیه معنایی واقعی — معماری قابل تعویض است.
- بذر فعلی تک‌فروشنده است؛ اسکیما (نقش‌ها، کاربران) از فروشندگان بیشتر پشتیبانی می‌کند.
- سشن‌های شبیه‌ساز به ازای هر `telegramUserId` هستند؛ دکمه‌ی بازنشانی در آزمایشگاه ربات موجود است.

## 🗺 پیشنهادهای بعدی

1. حالت وب‌هوک + اعتبارسنجی امضا برای ربات پشت URL عمومی.
2. اتصال درگاه پرداخت (مثل زرین‌پال) قبل از تأیید سفارش.
3. سرویس‌دهنده‌ی تعبیه واقعی + جستجوی ترکیبی `pgvector` (بردار + فیلتر در SQL).
4. تایم‌لاین سفارش برای هر قلم، تخفیف/کد تخفیف (فیلد تخفیف در اسکیما هست).
5. جداسازی چندفروشندگی (مالکیت محصول ↔ فروشنده) — اسکما برای نقش‌ها آماده است.
6. خط لوله رسانه (بندانگشتی با sharp، لایه انتزاعی ذخیره‌سازی S3/CDN).
7. ارسال لاگ ساختاریافته (خروجی JSON → Loki/Datadog) و هشدار روی سطح `error`.
