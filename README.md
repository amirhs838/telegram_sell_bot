# Silver Love — فروشگاه تخصصی نقره (پنل مدیریت + ربات تلگرام + دستیار فروش هوش مصنوعی)

سیستم فروش و مدیریت اختصاصی **فروشگاه نقره Silver Love** — نسخه ۲.۰. فروشنده محصولات و تصاویر را از پنل مدیریت فارسی/راست‌چین مدیریت می‌کند و **قیمت نهایی هر محصول را دستی ثبت می‌کند**؛ مشتری از طریق ربات تلگرام با یک **دستیار فروش هوشمند** گفتگو می‌کند، محصولات را با تصویر واقعی می‌بیند، سفارش می‌دهد، **رسید کارت‌به‌کارت** را ارسال می‌کند و ادمین پرداخت را به‌صورت **دستی** تأیید/رد می‌کند.

> ⚠️ این سیستم تک‌فروشگاهی (نه SaaS) است. هیچ موتور قیمت‌گذاری خودکار نقره وجود ندارد — قیمت محصول فقط از پنل و توسط فروشنده تغییر می‌کند و نرخ نقره صرفاً «اطلاعات مرجع» است.

| **استودیوی تصویر AI** | حذف پس‌زمینه با هوش مصنوعی ← انتخاب از **۸ پس‌زمینهٔ استودیویی آماده** (سفید لوکس، مشکی، مرمر، مخمل بژ، بازتاب نقره‌ای، تیرهٔ پریمیوم، صورتی، رویال) ← تولید عکس تبلیغاتی با نورپردازی جواهرات ← مقایسهٔ قبل/بعد ← تأیید صریح فروشنده؛ قواعد سفت: **هویت محصول هرگز تغییر نمی‌کند**، تصویر خام همیشه محفوظ است، خروجی فقط بعد از تأیید به گالری (به‌عنوان تصویر اصلی) متصل می‌شود و پست کانال همگام می‌ماند (`ImageStudioJob`) |
| **نرخ روز نقره در کانال** | ثبت نرخ از پنل ← **انتشار خودکار پست نرخ روز** در کانال (طراحی هماهنگ با برند، تاریخ/ساعت به منطقهٔ زمانی فروشگاه)؛ هر رکورد جدید یک پست مستقل، **انتشار مجدد همان رکورد = ویرایش همان پیام** (بدون پست تکراری)، وضعیت انتشار + خطا + دکمهٔ «تلاش مجدد» در پنل، ذخیرهٔ نرخ هرگز وابسته به تلگرام نیست |
| **ربات تلگرام** | **منوی حرفه‌ای ۶ دکمه‌ای** (محصولات، جستجو، مشاورهٔ خرید، سفارش‌ها، ارتباط، درباره) + خوشامد برندمحور، صفحهٔ «درباره» با نرخ روز واقعی، کارت محصول عکس‌دار با مشخصات نقره، «📸 تصاویر بیشتر»، جریان سفارش مکالمه‌ای، **دریافت رسید عکس‌دار**، اعلان ادمین، حالت شبیه‌سازی کامل |
| **آزمایشگاه ربات (Bot Lab)** | شبیه‌ساز گفتگو داخل پنل برای اجرای کامل جریان‌ها بدون توکن واقعی |
| **تنظیمات** | نام/توضیحات فروشگاه، آیدی پشتیبانی، مقاصد پرداخت، **فعال/غیرفعال‌سازی دستیار و تنظیم لحن فروشنده** (`aiEnabled`/`aiTone`) |
| **لاگ‌ها** | `ActivityLog` برای سفارش، پرداخت (دریافت/تأیید/رد + تأییدکننده)، نرخ نقره، انتشار کانال، هوش مصنوعی؛ بدون PII و اسرار |

### قواعد قطعی اعمال‌شده در کد

- **قیمت** = همان عددی که فروشنده در پنل ثبت می‌کند؛ سیستم/AI هیچ ضرب یا محاسبه‌ای انجام نمی‌دهد.
- **نرخ نقره** فقط دستی از پنل ثبت می‌شود؛ تغییرش هیچ محصولی را قیمت‌گذاری مجدد نمی‌کند.
- **تأیید پرداخت** فقط دستی توسط ادمین و از پنل؛ ثبت رسید به‌تنهایی پرداخت تلقی نمی‌شود؛ دوبار کلیک روی تأیید idempotent است (سفارش/موجودی دوباره تغییر نمی‌کند).
- سفارشِ دارای رسیدِ در انتظار بررسی **خودکار منقضی نمی‌شود**؛ پس از رد، مشتری می‌تواند رسید اصلاح‌شده بفرستد.

## 🏗 معماری

```
فروشنده ──> پنل مدیریت (SPA در "/" — مسیریابی hash، راست‌چین، shadcn/ui)
             │
             ▼
        مسیرهای API در Next.js (/api/**)  ← احراز هویت: کوکی سشن یا Bearer token
             │
             ▼
   Prisma + SQLite (WAL)  ← تنها مرجع حقیقت (تنظیمات تلگرام هم اینجاست)
             ▲                        │
             │ دسترسی مستقیم Prisma   │ انتشار / همگام‌سازی / اعلان
   mini-services/bot-service          ▼
   (پورت 3002، bun --hot)      Telegram Bot API (long-polling پویا)
             ▲
   /simulate  ◀── آزمایشگاه ربات مدیر (پروکسی از طریق /api/bot/simulate)
   دستیار AI ◀── HTTP داخلی با x-internal-key (/api/internal/ai-assistant)
```

- **SPA تک‌مسیره** — همه‌ی ناوبری hash است (`#/products`، `#/payments`، `#/silver-rate` و…).
- **ربات = سرویس مستقل bun** — ماشین حالت (`BotSession`)، سفارش تراکنشی، دریافت عکس رسید (`getFile` → ذخیرهٔ خصوصی → ردیف `Payment`) و فراخوانی نقطه‌پایان AI.
- **حافظهٔ AI** — مکالمه در جدول `ChatMessage` ماندگار است و از ری‌استارت سرویس عبور می‌کند؛ تاریخچه محدود (۱۲ پیام آخر) تا مصرف توکن کنترل شود.
- **حالت شبیه‌سازی تلگرام** — بدون توکن، همه‌چیز در `ActivityLog` ثبت می‌شود و کل چرخه دمو-پذیر است.

## 🚀 راه‌اندازی

```bash
bun install
cp .env.example .env          # مقادیر را ویرایش کنید
bun run db:push               # ساخت/همگام‌سازی اسکیمای SQLite
```

### لایهٔ دوتایی هوش مصنوعی (`src/lib/ai/provider.ts`)

1. **اولویت اول — کلید فروشنده** (`ZAI_API_KEY`): تمام تماس‌های چت (دستیار فروش ربات) و ساخت تصویر روی نقطهٔ پایانی عمومی `api.z.ai/api/paas/v4` با مدل‌های قابل‌تنظیم اجرا می‌شود.
2. **جایگزین خودکار — دروازهٔ پلتفرم** (`z-ai-web-dev-sdk`): اگر کلید تنظیم نشده باشد، نامعتبر باشد (۴۰۱) یا محدودیت نرخ (۴۲۹) بدهد، تماس بدون دخالت کاربر به دروازهٔ پلتفرم برمی‌گردد؛ وضعیت سلامت کلید ۱۰ دقیقه کش می‌شود تا تأخیر اضافه‌ای تحمیل نشود و سپس دوباره امتحان می‌شود.
3. **پس‌زنش ۴۲۹** — هر دو مسیر با احترام به هدر `Retry-After` و رشد نمایی دوباره تلاش می‌کنند؛ خطاها همیشه پیام فارسی روشن به فروشنده می‌دهند.

پاسخ پنل/لاگ‌ها هیچ‌وقت مقدار کلید را نشان نمی‌دهند — فقط `userKeyConfigured` و سلامت آن.

## 💳 فرایند پرداخت دستی (چک‌لیست ادمین)

1. **تنظیمات → اطلاعات پرداخت**: کارت بانکی فروشگاه را ثبت و فعال کنید.
2. مشتری در ربات سفارش می‌دهد → پیام «مبلغ قابل پرداخت + اطلاعات کارت» را می‌بیند.
3. مشتری عکس رسید را در همان چت می‌فرستد → ربات رسید را خصوصی ذخیره، سفارش را «رسید در انتظار بررسی» می‌کند و به ادمین اطلاع می‌دهد.
4. **پنل → پرداخت‌ها**: رسید را ببینید، مبلغ/واریزکننده/شماره پیگیری را با سفارش مقایسه کنید → «تأیید پرداخت» (با تأیید نهایی) یا «رد پرداخت» (دلیل الزامی — به مشتری اعلام می‌شود و می‌تواند رسید جدید بفرستد).
5. پس از تأیید: وضعیت پرداخت «پرداخت‌شده»، سفارش «تأییدشده»؛ کد رهگیری پستی را در جزئیات سفارش وارد کنید.

## 🤖 دستیار فروش — قواعد رفتاری

شخصیت، لحن و قواعد ضدتوهم در `src/lib/ai/assistant.ts` (SYSTEM_PROMPT) نوشته شده‌اند: پاسخ‌های طبیعی فارسی، نیازسنجی پله‌ای، فقط داده‌های واقعی دیتابیس، اعلام صادقانهٔ «نمی‌دانم» و پیشنهاد اپراتور انسانی، عدم ادعای انسان‌بودن. تنظیمات `aiEnabled`/`aiTone` از پنل (تنظیمات) اعمال می‌شوند؛ خاموش‌کردن دستیار فقط جستجوی قطعی را فعال نگه می‌دارد.

## 🧪 تست‌های سرتاسری انجام‌شده

- ورود/خروج + پشتیبانی Bearer (رفع مشکل «نشست شما منقضی شده» در iframe)؛ مسیرهای محافظت‌شده 401.
- گالری چندتصویری: آپلود، تصویر اصلی، ترتیب، حذف؛ همگام‌سازی `imageUrl` با تصویر اصلی.
- نرخ نقره: ثبت + تاریخچه + فعال/غیرفعال؛ پرسش «نرخ نقره» از AI → همان نرخ دیتابیس.
- پرداخت: رد بدون دلیل ⇒ 422 با پیام فارسی؛ تأیید دوباره ⇒ idempotent (`alreadyApproved`)، بدون ردیف/کسر موجودی تکراری؛ سفارش → `paid`+`confirmed`.
- رسید خصوصی: دسترسی ناشناس ⇒ 401؛ نمایش در پنل با Blob احراز هویت‌شده.
- جریان کامل ربات (شبیه‌ساز): کارت عکس‌دار با قیمت ثابت + عیار/وزن/سایز/کد، «تصاویر بیشتر»، سفارش ۲عددی → مبلغ دقیق ۱٬۵۶۰٬۰۰۰، اطلاعات کارت فعال، دریافت رسید، اعلان ادمین.
- چیدمان موبایل/دسکتاپ، فوتر چسبان، lint و tsc پاک.

| ربات عکس نمی‌فرستد | تصویر اصلی محصول ست شود؛ در حالت mock فقط لاگ ثبت می‌شود |
| `SQLITE_BUSY` | `connection_limit=2` را نگه دارید؛ WAL فعال است |
| بازنشانی داده‌های نمونه | ‏`bun scripts/seed.ts --reset` |

## ⚠️ محدودیت‌های شناخته‌شده

- رسیدها روی دیسک محلی و پشت مسیر احراز هویت‌شده‌اند؛ برای ترافیک واقعی، انتقال به S3/CDN با URL امضاشده توصیه می‌شود.
- بردار تعبیه همچنان هش محلی است (واژگانی، نه معنایی عمیق).
- محدودساز نرخ/کش‌ها درون‌حافظه‌ای‌اند — مناسب تک‌نمونه.
- مکالمهٔ اپراتور انسانی در این نسخه داخل ربات ادامه نمی‌یابد؛ پرچم درخواست + دلیل در پنل (مشتریان) ثبت می‌شود.
- تأیید پرداخت صرفاً دستی است؛ هیچ تطبیق خودکار بانکی وجود ندارد (عمداً، طبق تصمیم محصول).
